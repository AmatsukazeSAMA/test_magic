# 可见原像素分层、时间轴回合成与绘制态补审

本轮基于原交接提交 `6061ae798fa0b4c7d8dca946197e381eed56e738` 继续工作。人物像素唯一来源是附件1 `source/original.mp4`；附件2只保留为编号和提醒参考。两份原视频、原411组 `cels/` 和原片时间表未改写。

## 先分清三个验收问题

1. **像素/时间轴完整性**：原像素是否改动、遗漏、重复归属，4763帧的PTS、末帧时长和音频是否改变。可以做精确机器检查。
2. **语义分层质量**：手套是否归入人物、字幕是否误连衣服、人物/道具接触是否拆净。必须另外看图，不能用“全层叠加等于原片”证明。
3. **绘制态覆盖**：不同手势、过渡、眼睑、衣纹重描是否均有来源证据；同稿曝光、镜头运动、花瓣不能冒充新原画。不能用“已解码4763帧”或“原目录有411项”替代这项审计。

本轮有可编辑分区和完整性诊断，**没有宣称已找回全部作者原画、完成干净人物抠图或获得用户绘画验收**。全片重绘仍依赖用户后续人设，不在本轮擅自生成。

## 1. 代表构图透明分区

`layers/<panel_id>/` 共覆盖411个参考构图、408个不同原片帧、56组，导出1,398张非空、1920×1080 RGBA PNG。画布坐标与源帧一致，未缩放、变形、改色或补画。

| 分区名 | 含义 | 非空代表构图数 |
|---|---|---:|
| `background_observed` | 当前源帧可见的背景区域，不是补全后的无人物背景 | 411 |
| `environment_or_props` | 可辨认环境/道具；部分仍为接触组合而非逐件资产 | 54 |
| `subject_visible` | 可辨认的可见人物；不代表遮挡下全身完整 | 347 |
| `subtitles_visible` | 能独立确认的文字像素；不是所有歌词均拆净 | 86 |
| `effects_visible` | 能独立确认的橙色转场、花瓣等效果 | 131 |
| `unresolved_visible` | 无法可靠归属、断开的部件、混合边界等，显式保留 | 369 |

Alpha仅为0/255的**像素归属蒙版**，不是复原原始半透明度。可见RGB逐像素复制原片；已压在背景上的抗锯齿、压缩色晕仍可能存在。把人物层换到新背景时，仍需边缘处理。

每组有 `PROVENANCE.json`；总索引见 [layer_manifest.json](data/layer_manifest.json)。[分层工作台](分层工作台.html) 可离线开关图层、切换衬底、对照原图、筛选工作段/组别/状态、查看原尺寸PNG。411个目录源帧实际落在31段，剩余段不是靠这一页“自动审核通过”。

## 2. 全片逐帧分区与回合成

`frame_labels/F000000.png`–`F004762.png` 是六类像素归属的索引PNG，不包含人物RGB。每一帧使用本帧原像素独立计算；没有用最近参考姿态代替当前帧，也没有把附件2的停留时间当成原片曝光。

- 清单：[frame_layer_manifest.json](data/frame_layer_manifest.json)。记录每帧源PNG/蒙版哈希、分类像素数、警告、路由依据、原帧号和整数PTS。
- 全部4763帧分区已生成，无源帧直接回退；其中3792帧含待判定像素，55帧没有可证明的场景分类（包含纯背景/无人物段），并未因此自动标成干净人物层。语义批准仍为0。
- 绑定：[frame_bindings.json](data/frame_bindings.json)。分区覆盖与人物身份绑定分别记录；未确认的原画身份不猜填。
- 源帧缓存检查：[FRAME_CACHE_VERIFICATION.json](data/FRAME_CACHE_VERIFICATION.json)。全部4763个缓存RGB与重新从附件1独立解码所得RGB一致。
- 无损诊断母版：`renders/all_frames_lossless.mp4`，逐帧精确PTS、RGB无损编码，体积过大不放入Git；可复现。[检查报告](renders/all_frames_lossless.verification.json)。
- [查看副本](renders/all_frames_preview.mp4) 与 [检查报告](renders/all_frames_preview.verification.json)：便于播放的有损H.264，原音频包复制。查看副本不声称像素无损。

原片时间基为 `1/16000`，4763个视频帧，视频结束于2543333 ticks，末帧533 ticks；音频比视频略长，**不能用 `-shortest` 或视频帧数限制截断音频**。新工具检查全部PTS、每帧时长、末帧、帧数、尺寸；无损母版还检查每帧RGB，并比较全部压缩音频包及时间戳。没有用“约29.97fps”重算时间。

## 4. 绘制态覆盖审计与补帧

全片4763帧、37段均经原视频原尺寸RGB指纹及颜色/墨线特征扫描；244个初筛变化点全部作联系表分流，再查低差异细变和原尺寸关键线条。4049个不同RGB合成画面**不是4049张原画**，特征阈值也不是完整性证明。

## 5. 恢复、验证与回退

便携命令见[仓库README](../README.md#便携处理与复现)。新工具仅使用Python标准库及固定版本NumPy/Pillow/SciPy，加FFmpeg/ffprobe；不需要模型API密钥、浏览器凭据、用户本地Codex或原电脑路径。

- `scripts/verify_layers.py` 独立检查源哈希、帧号/PTS、透明画布、原RGB、蒙版无重叠/无缺口和精确重合成，报告明确 `semantic_acceptance: false`。
- 最终46项单元/集成测试通过，另有9项工作台自检；覆盖损坏源图、漏像素、重复覆盖、错误帧号/PTS、路径越界、输出覆盖保护、时间轴末帧/音频、索引蒙版、遮挡分类与色彩元数据等。[聚合检查](data/PIPELINE_VERIFICATION.json)同时核对1398张图层、4763张索引蒙版、83张补审原图及所有报告哈希。
- 原有 `scripts/verify_handoff.py` 继续核验原交接资产；历史 `VERIFICATION.json` / `BROWSER_CHECK.json` 不冒充本轮新检查。
- 无损母版生成时的统计尚未包含后续五个补充观察；最终 `frame_bindings.json` 已链接五个观察、66个明确曝光帧。它们只补审计元数据，不改变每帧像素或时序，未据此重复生成画面。
- 新离线工作台的结构、JavaScript语法和全量资产路径经过检查；**实际浏览器交互QA受云浏览器file URL与执行器loopback隔离所限，未完成，不记为通过**。
